# Upgrade Warden（仮称）商品設計書

最終更新: 2026-11-16（バージョン 0.1 開発中。まだ WordPress のプラグインとしては動きません）

04 の商品は「PHP のバージョンアップで壊れる古いプラグイン・テーマを、検査して直す」プラグインです。
選定の経緯と根拠は `docs/market-research.ja.md` にあります。**選定は僅差で、確信度は高くありません。** 先にそちらの第2章と第4章を読んでください。

## 0. この文書の読み方

### 0.1 状態の表記

| 表記 | 意味 |
|---|---|
| **実装済み** | コードがあり、自動テストが通り、下の 0.2 の範囲で実物の PHP で確かめてある |
| **設計済み** | 実現方法をこの文書で定めたが、コードはまだない |
| **未定** | 方法か前提がまだ決まっていない |

### 0.2 「実物の PHP で確かめた」の範囲

- 確かめた版は **PHP 7.4.33／8.0.30／8.1.34／8.2.35／8.3.36／8.4.27／8.5.12** の7つです（npm の php-wasm 3.1.64。WebAssembly 版の PHP で、公式のソースから作られたものですが、レンタルサーバーの PHP そのものではありません）。
- **PHP 8.6 は確かめていません。** php-wasm に 8.6 がなく、公式ソースからのビルドはこの開発環境の権限で止められました。8.6 に関する内容は、公式の変更記録（UPGRADING）の原文だけに基づき、製品の中でも「文献のみ」と区別して表示します。
- PHP 7.0〜7.3 の実物はありません。「7.2 から非推奨」のような 7.4 より前の版の数字は、公式の変更記録によるものです。
- **本物の WordPress の上では、まだ一度も動かしていません。** 管理画面もデータベースの処理もまだありません。

## 1. 商品コンセプト

### 1.1 一言でいうと

**「直すところまでやる。直した結果は、実物の PHP で確かめてある。」**

### 1.2 なぜ検査ではなく修正か

検査（スキャン）だけの無料プラグインは、2026年の秋だけで10本以上が公開されました（`docs/market-research.ja.md` 4.1。検索結果の抜粋に基づく情報）。検査は入口として無料で提供し、売り物にはしません。
調査の範囲では、管理画面で古いコードを自動修正するプラグインは見つかりませんでした。

### 1.3 3つの条件との対応

| 条件 | 対応 |
|---|---|
| 1. 求められている／諦められてきた | 保守が止まり評価も低い PHP Compatibility Checker がなお約20万サイトで使われている（抜粋）。標準のルール集 PHPCompatibility は PHP 8.x 対応の安定版が出ていない（リポジトリのタグを直接確認）。修正は制作会社に 3〜12万円で外注されている（抜粋） |
| 2. 人手では作業工程が多すぎる | 1つのルールにつき「主張」「確かめるコード」「修正後のコード」を用意し、7つの版の実物の PHP で実行して照合する。公式の変更記録は PHP 8.0〜8.6 だけで、互換性のない変更が約440項目、非推奨が約180項目ある（UPGRADING の項目数を直接数えた値）。これを1件ずつ実機で裏づける作業は、人手では割に合わない |
| 3. 無料で完成できる | PHP、検証用の実行環境（php-wasm）、構文解析ライブラリ（PHP-Parser、BSD-3-Clause）、公式の変更記録、検証用の実在コード（WordPress 本体）は、すべて無料で入手した。有料の API・サーバー・データは使っていない |

条件2について正直に書くと、**現時点の規模（ルール17種類、検証27件）はまだ「人手では作れない」量ではありません。** できているのは、その量を誤りなく積み上げるための仕組みです。量はこれから積みます（第7章）。

## 2. 3本の柱

| 柱 | 内容 | 状態 |
|---|---|---|
| ① 実機で検証したカタログ | 「この書き方は PHP x.y で非推奨、PHP x.z で動かなくなる」という主張を、1件ずつ実物の PHP で実行して確かめる。確かめていない主張は製品に入れない。確かめられない版（8.6）は「文献のみ」と明示する | 実装済み（仕組み）。件数は第5章 |
| ② 自動修正 | 検出した箇所を書き換える。書き換え後のコードが、**元のコードと同じ出力を全バージョンで返す**ことを実機で確かめた種類だけを提供する。修正後のコードは元の PHP の版でも動くので、「先に直してから PHP を切り替える」順序が取れる | 実装済み（エンジン。9種類）。管理画面・バックアップ・巻き戻しは設計済み |
| ③ 実行時の記録 | 静的な検査では分からないもの（値によって起きる型エラー、動的プロパティなど）を、本番で実際に出た警告・エラーとしてプラグイン・テーマ別に記録する | 設計済み |

## 3. Free と Pro の境界

03（Checkout Warden）と同じ考え方です。**診断は無料、治療と運用が有料。**

| 機能 | 版 | 状態 |
|---|---|---|
| プラグイン・テーマの検査（どのファイルの何行目が、どの版から、どうなるか） | Free | エンジンは実装済み。WordPress への組み込みは設計済み |
| 移行先の版ごとの判定（8.0〜8.6 を1回の検査で） | Free | 実装済み（エンジン） |
| ガード済みのコードの区別（`function_exists()` や版の判定の内側は「壊れる」と報告しない） | Free | 実装済み |
| 「実機で確認済み」と「文献のみ」の区別の表示 | Free | 実装済み（エンジン） |
| 実行時の記録（直近の分だけ） | Free | 設計済み |
| **ワンクリック修正**（差分の確認、バックアップ、巻き戻し） | Pro | 修正エンジンは実装済み。差分・バックアップ・巻き戻しは設計済み |
| 定期検査と、更新を入れる前の検査 | Pro | 設計済み |
| 実行時の記録の長期保存と通知 | Pro | 設計済み |
| 制作会社向けの報告書（顧客に渡す調査報告） | Pro | 設計済み |
| 削除された関数の互換層 | Pro | 未定（需要の新しい証拠が弱い。調査記録 4.4） |

WordPress.org の審査の手引きに「他のテーマ・プラグインの編集を要求するな」とあるため（抜粋）、**ファイルを書き換える機能は Pro にだけ入れ、無料版には一切入れません。** 修正エンジンは `premium/` に置いてあり、Freemius が無料版を作るときに取り除かれる想定です。

## 4. 仕組み

```
開発時（tools/、製品には入らない）
  実物の PHP 7.4〜8.5 ──┬─ 関数・定数の一覧と非推奨の印を取り出す
                        │        │
  公式の変更記録 ───────┼────────┴─ 両方が一致したものだけ ─→ data/catalog/（製品に入る）
  （UPGRADING）         │                 片方だけ ─→ 要確認の一覧（製品に入らない）
                        │
                        └─ フィクスチャ（主張＋コード＋修正後のコード）を全版で実行
                                 └─ 主張と照合、修正後の出力が元と同じか確認 ─→ observed.json（記録）

製品（src/、premium/）
  PHP ファイル ─→ 構文木 ─→ ルール ─→ 検出結果（どの版から警告・変化・不能か、ガードの有無、根拠の種類）
                                          │
                                          └─（Pro）修正：検出結果の位置への小さな書き換え
                                                    ─→ 構文として読めることを確認 ─→ 書き戻し
```

### 4.1 二重照合

関数や定数の「削除された」「非推奨になった」は、**実物の PHP が示し、かつ公式の変更記録に記載があるもの**だけをカタログに入れます。

実機の比較だけでは誤ります。実際に、PHP 8.1 と 8.2 の実行環境を比べると `imagebmp()` など4つの関数が「消えた」ように見えましたが、これは PHP の変更ではなく実行環境の作り方の違いでした。二重照合がこれを自動で除外しました。

公式の記載が関数名を挙げず文章でまとめている場合（「Zip の手続き型 API は非推奨」など）は、手で対応づけを書きます。その注記は**公式の原文を一字一句引用する**必要があり、引用が原文になければカタログの生成が失敗します。

### 4.2 フィクスチャ

`tools/fixtures/*.fixture` に、ルール1件ごとに次をまとめます。

- 主張（どの版から非推奨か、どの版から挙動が変わるか、どの版から動かないか）
- その書き方を実際に使う小さなプログラム
- 修正後のプログラム（修正を提供する場合）

これを全バージョンで実行し、主張と照合します。修正後のプログラムは、全バージョンで警告なしに動き、**元のプログラムが PHP 7.4 で出した出力と同じ出力**を返さなければなりません。

テストは、スキャナが報告する内容とフィクスチャの主張が一致すること、修正エンジンの出力がフィクスチャの「修正後」と一字一句一致することを確かめます。つまり、**実機で動かしたものと、製品が出すものが同じ**であることが保証されます。

この仕組み自体が正しく不一致を検出することは、わざと誤った主張と誤った修正を与えて確かめました（10件の不一致をすべて検出）。

### 4.3 スキャナ

- 文字列の検索ではなく構文木で判定します。`each()` の呼び出しと、`$list->each()` というメソッド呼び出しを区別します。
- 最新の文法で読めないファイルは PHP 7.4 の文法で読み直し、PHP 8.0 で削除された書き方を特定します。
- 同じプラグインが自分で定義している関数（自前の `each()` など）は、PHP の関数として報告しません。
- 検出結果は移行先の版に依存しません。1回の検査で、8.0〜8.6 のどの版についても判定できます。

### 4.4 修正

- ファイル全体を整形し直すのではなく、検出した位置だけを書き換えます。それ以外は、空白もコメントも1バイトも変わりません。
- 書き換えた結果が構文として読めなければ、そのファイルには何もしません。
- ある修正が別の修正の内側にある場合は、検査と修正を繰り返して順に片づけます。

### 5.3 検証の結果

| 対象 | 方法 | 結果 |
|---|---|---|
| フィクスチャ 27件 | 7つの版の実物の PHP で実行し、主張と照合 | 不一致0件。うち15件は修正後のコードも実行し、全バージョンで元と同じ出力 |
| 自動テスト 73件 | 同じ7つの版で実行 | すべて通過 |
| 自分自身のコード | スキャナにかける（PHP 8.6 向け） | 検出0件。最初は自分のコードに PHP 8.4 の非推奨（`array $rules = null`）が2か所あり、修正した |
| WordPress 7.1.4（1,900ファイル・21.7MB） | PHP 8.5 向けに検査 | 約8秒。「動かなくなる」「挙動が変わる」は0件（PHP 8.5 対応を謳うコードに誤って「壊れる」と報告していない）。非推奨20件、ガード済み39件 |
| WordPress 4.0（2014年、524ファイル） | 自動修正を適用し、修正前後を実物の PHP でコンパイル | 下の表 |

WordPress 4.0 に 235件の修正（33ファイル）を適用した前後：

| 実物の PHP | コンパイルできないファイル | コンパイル時の非推奨警告 |
|---|---|---|
| 7.4.33 | 2 → 2 | 137 → 0 |
| 8.0.30 | 13 → 2 | 3 → 3 |
| 8.5.12 | 13 → 2 | 13 → 5 |

残った2ファイルは「ループの外の break」で、安全な自動修正をまだ持っていません。修正前の PHP 7.4 でも既に読み込めなかったファイルです。

**この結果の読み方についての注意**

- 「コンパイルできる」は「正しく動く」ではありません。WordPress 4.0 にはこのほか、削除された関数の呼び出し（`each()` 18件、`mysql_*` など）が残っており、これらは実行された時点で止まります。修正後の WordPress 4.0 が PHP 8 で動くことは確かめていませんし、動かないはずです。
- WordPress 7.1.4 の非推奨20件は該当箇所を目で確認し、実在する書き方でした（同梱の sodium_compat の32ビット用コードに `Foo $x = null` が18か所など）。ただし、**見逃しがどれだけあるかは測れていません。**
- 実物の PHP のコンパイル結果とスキャナの検出を突き合わせたことで、スキャナの見逃しが2種類見つかり（ループの外の break、バッククォート）、どちらもルールを追加しました。同じ方法で、まだ見つかっていない見逃しがあるはずです。

## 9. オーナーにしか決められない／できないこと

| 事項 | 理由 |
