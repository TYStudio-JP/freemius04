## 1. 商品コンセプト

### 1.1 一言でいうと

**「直すところまでやる。直した結果は、実物の PHP で確かめてある。」**

### 1.2 なぜ検査ではなく修正か

検査だけの無料プラグインは、2026年の秋だけで10本以上が公開されました（調査記録 4.1、検索結果の抜粋）。検査は入口として無料で提供し、売り物にはしません。
調査の範囲では、管理画面で古いコードを自動修正するプラグインは見つかりませんでした。

### 1.3 3つの条件との対応

| 条件 | 対応 |
|---|---|
| 1. 求められている／諦められてきた | 保守が止まり評価も低い PHP Compatibility Checker がなお約20万サイトで使われている（抜粋）。標準のルール集 PHPCompatibility は PHP 8.x 対応の安定版が出ていない（タグを直接確認）。修正は制作会社に 3〜12万円で外注されている（抜粋） |
| 2. 人手では作業工程が多すぎる | 公式の変更記録（PHP 8.0〜8.6）の **602項目すべて**に判定を付け、検出できるものは規則にし、**899個**の検証用プログラムを**7つの版の実物の PHP**で実行して照合した（第5章）。1項目ずつ「主張を書く→動くコードを書く→7版で実行→食い違えば主張を直す→別の担当が反証する」を積み上げた量で、人手では割に合わない |
| 3. 無料で完成できる | PHP、検証用の実行環境（php-wasm）、構文解析ライブラリ（PHP-Parser、BSD-3-Clause）、公式の変更記録、WordPress 本体と SQLite 連携、検証用の実在コード（GitHub の公開プラグイン）は、すべて無料で入手した |

## 3. Free と Pro の境界

**診断は無料、治療と運用が有料。**

| 機能 | 版 | 状態 |
|---|---|---|
| プラグイン・テーマの検査（ファイル・行・どの版から何が起きるか） | Free | 実装済み |
| 移行先の版（8.0〜8.6）の切り替え。再検査は不要 | Free | 実装済み |
| チェックの内側のコード（版の判定など）を「壊れる」と報告しない | Free | 実装済み |
| 「実機で確認済み」と「文献のみ」の区別 | Free | 実装済み |
| **自動修正**（変更内容の確認、バックアップ、巻き戻し） | Pro | 実装済み |
| 定期検査、更新前の検査 | Pro | 未実装 |
| 実行時の記録 | Free（直近）／Pro（長期・通知） | 未実装 |
| 制作会社向けの報告書 | Pro | 未実装 |

ファイルを書き換える機能は Pro（`premium/`）にだけ置きます。WordPress.org の審査の手引きに「他のプラグインの編集を要求するな」とあるためです（抜粋）。

## 4. 仕組み

```
開発時（tools/、製品には入らない）
  公式の変更記録 ─→ 全602項目の台帳（tools/ledger/）
                        │  規則にできるもの
                        ▼
  検証用プログラム（主張＋コード＋修正後のコード）─→ 実物の PHP 7.4〜8.5 で実行
                        │  主張と一致、修正後は元と同じ出力       ─→ *.observed.json（記録）
                        ▼
  規則（src/Engine/Rules/）  ←── テストが「規則の主張＝検証済みの主張」を強制

製品
  PHP ファイル ─→ 構文木 ─→ 規則 ─→ 検出結果（警告・変化・不能の版、チェックの有無、根拠の種類）
                                         └─（Pro）修正：検出位置への小さな書き換え ─→ バックアップ ─→ 書き戻し
```

- **二重照合**：関数・定数の削除と非推奨は、実物の PHP が示し、かつ公式の記載があるものだけを入れます。実行環境の作り方の違いで「消えた」ように見えた関数4つを、これで自動的に除外しました。
- **台帳**：公式記録の1項目ごとに「規則で検出」「関数・定数の一覧で対応」「実行時にしか分からない」「構文から判別できない」「対象外」のどれかと、その理由を原文の引用付きで記録しています。
- **反証**：14区画それぞれを、作った担当とは別の担当が点検しました。項目数の数え直し、検証の再実行、似た正しいコードでの誤検知探し、WordPress 本体での確認です。点検で見つかった誤りの例は 5.3。
- **修正**：ファイル全体を整形し直さず、検出位置だけを書き換えます。結果が構文として読めなければ何もしません。

### 5.2 実機が公式の記載を正した例

公式記録は「何が変わったか」は書いても「どの書き方で警告が出るか」までは書いていません。実機で動かして初めて分かったことの例です。

- 8.4：セッションの設定を「変更すると非推奨」とあるが、既定値に設定しても何も出ない。既定値以外のときだけ出る。
- 8.4：XML のハンドラーに文字列を渡すのは「非推奨」とあるが、`xml_set_object()` より前に設定すると例外で止まる（動かなくなる）。
- 8.1：`PDO::FETCH_SERIALIZE` は単独では何も出ず、`FETCH_CLASS` と組み合わせたときだけ出る。
- 7.4／8.0：ループの外の `break` は、到達しなくてもファイル全体の読み込みが失敗する。

### 5.3 点検（反証）で直した誤りの例

- 非推奨の関数を `function_exists()` で囲んだコードを「チェックの内側だから安全」としていた。実機では内側でも警告が出たため、安全とするのは版の判定の内側だけに改めた。
- 区画同士の食い違い2件（親クラスのない `parent::`、戻り値の型のない `jsonSerialize()`）。どちらも実機の結果に合わせた。
- 検査を動かしている PHP に関数の有無を尋ねる規則があり、WordPress の中では他のプラグインの読み込み状況で結果が変わり得た。どこでも同じ結果になるよう直した。

### 5.4 本物の WordPress での確認

WordPress 7.1.4 を SQLite で導入し、有効化・分割検査・結果画面・修正の確認・適用・巻き戻しを、31項目で自動確認しています（`tools/wp-check.mjs`）。PHP 7.4.33／8.2.35／8.5.12 で31項目すべて通過しました。
巻き戻しは「修正後に変更されたファイルは上書きしない」ことも確かめています。

### 5.5 実在のコードでの確認

| 対象 | 結果 |
|---|---|
| WordPress 7.1.4（1,900ファイル） | PHP 8.5／8.6 向けで「壊れる」「挙動が変わる」は0件 |

**Elementor の件**：`includes/libraries/bfi-thumb/bfi-thumb.php` の画像回転処理は、`imagerotate()` の戻り値を `is_resource()` で確かめています。PHP 8 以降はリソースではなくオブジェクトが返るため、同じ処理を実物の PHP で動かすと、7.4 では回転に成功し、8.0 と 8.5 では毎回「回転失敗」のエラーを返しました。
対象は GitHub の Elementor の現行ソース（バージョン表記 4.5.0、Requires PHP 7.4）です。**この回転処理が通常の操作で実際に呼ばれるかは確かめていません。**

非推奨の報告（約240件）が正しいかは、規則ごとに2人の担当が実機で判定しています（結果は `docs/` に追記予定）。

## 9. オーナーにしか決められない／できないこと

| 事項 | 理由 |
|---|---|
| PHP 8.6 のビルドの許可 | `./buildconf` の実行が権限の判定で止められる。許可ルールの追加が必要 |
| wordpress.org・php.net の閲覧の許可 | 競合のインストール数や公式統計、スラッグの空きを一次情報で確かめるため。環境の設定の「ネットワークアクセス」で許可ドメインに追加する |
| Freemius への製品登録 | アカウントの操作が必要 |
| Elementor の不具合を報告するか | 外部への公開にあたるため |
