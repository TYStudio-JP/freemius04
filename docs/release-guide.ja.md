## 2. Freemius の設定（オーナーの操作）

03（Kessai Guard）と同じ流れです。

### 2.1 製品の登録

1. Freemius のダッシュボードで「Add Product」→ WordPress Plugin。
2. Title `Upgrade Warden`、Slug `upgrade-warden`、**Paid version slug `upgrade-warden-premium`**（コードの `premium_slug` と合わせてあります。ここが食い違うと、無料版から購入版への切り替えで不具合になります）。
3. プランは「無料」と「Pro」の2つ。Pro の内部名は `pro`。

### 2.2 価格（確定済み・2026-11-16 一任）

| サイト数 | 年額 | 買い切り |
|---|---|---|
| 1 サイト | $49 | $149 |
| 5 サイト | $99 | $299 |
| 無制限 | $199 | $599 |

14日間の無料トライアル（支払い方法の登録なし）。コード側は設定済みです。返金の条件は 03 と同じ（14日・Flexible）を想定しています。

### 2.3 キーの記入

`upgrade-warden.php` の3か所に、ダッシュボードの値を入れます。

| 定数 | 値のある場所 |
|---|---|
| `UPGW_FS_PRODUCT_ID` | Product ＞ Settings ＞ Keys の ID |
| `UPGW_FS_PUBLIC_KEY` | 同じ画面の Public Key（`pk_` で始まる方。**Secret Key は入れない**） |
| `UPGW_FS_GATEKEEPER` | SDK Integration の画面に出るコード例の `wp_org_gatekeeper` の値 |

3つとも空のあいだは開発モードで動きます（ライセンスなし、更新なし）。テストは空のままで動きます。

### 2.4 SDK

Freemius SDK（2.13.5）は `vendor/freemius/` に置きます（git の対象外）。03 の `vendor/freemius` をそのまま複製してあります。
新しく取り出した場所では、`composer install --no-dev` か、03 からの複製で用意してください。

### 2.5 ビルドとアップロード

```
node tools/build-zip.mjs
```

- `build/upgrade-warden.zip` … **Freemius にアップロードするもの**（Pro。`premium/` と `languages/` を含む）
- `build/upgrade-warden-free-preview.zip` … 無料版の見本（確認用。申請には使わない）

スクリプトは、無料版に Pro のコードへの言及が残っていれば失敗して一覧を出します。
Deployment 画面の「Add Freemius as plugin contributor」は**チェックを外して**アップロードします（readme の Contributors を `tystudiojp` だけにするため）。

### 2.6 無料版と Pro の作り分け

- Pro のコードはすべて `premium/` にあります。メインファイルのヘッダーで `@fs_premium_only /premium/, /languages/` と宣言しています。
- 無料版のコードの中で Pro に触れるのは、`if ( upgw_fs()->is__premium_only() ) { ... }` の中と、名前が `__premium_only` で終わるメソッドだけです。Freemius はこれらを取り除いて無料版を作ります。
- **無料版の機能に、ライセンスで鍵をかけたものはありません**（WordPress.org の規約5）。実行時の記録の保存日数（7日）は無料版の固定値で、Pro は `premium/` のコードがフィルターで 90日にします。
- 無料版は翻訳ファイルを同梱しません（translate.wordpress.org の訳を使う）。Pro は `languages/` の日本語訳を自分で読み込みます。
- アンインストール時の削除は、Freemius の `after_uninstall` から呼びます（`uninstall.php` は置かない。Freemius の決まり）。

## 3. WordPress.org への申請（無料版）

**WordPress.org は1アカウントにつき審査待ちを1件しか受け付けません。** 2026-11-19 時点で Kessai Guard が審査待ちです。その審査が終わってから申請します。

1. Freemius が生成した無料版の zip を取得する（Deployment 画面）。
2. 1.2 の 2 の確認をする（見本との照合、Plugin Check、`wp-check.mjs --free`）。
3. WordPress.org のプラグイン申請ページから提出する。スラッグは `upgrade-warden`。
4. 承認後、SVN の `assets/` にアイコン・バナー・スクリーンショット（readme の Screenshots の順に4枚）を置く。**素材はまだ作っていません。**
5. 公開後、translate.wordpress.org で日本語訳を登録する（元データは `languages/upgrade-warden-ja.po`。Pro 用の文言も含みますが、無料版にない文言は取り込まれません）。

審査で指摘が想定される点:

- **プラグイン名**: 表示名は「Upgrade Warden – PHP 8 Compatibility Scanner」。既存の「PHP Compatibility Checker」（WP Engine）と紛らわしくならないよう、その語の並びは避けました。無料版は修正をしないので、名前に「Fixer」は入れていません。
- **他のプラグインのファイルを書き換える機能**: Pro にだけあります。無料版には書き換えるコードがありません。
- **有効なプラグインの読み込み順を変える**: 実行時の記録をオンにしているあいだだけ、自分を先頭にします（ほかのプラグインの読み込み中のメッセージを拾うため）。既定はオフで、readme の FAQ に書いてあります。指摘された場合は、この並べ替えをやめても記録自体は動きます（読み込み中のメッセージだけ拾えなくなる）。
- **外部通信**: ありません。Freemius のオプトインは `readme.txt` の「External services」に記載済みです。
- **保存するデータ**: 実行時の記録は、PHP のメッセージ・ファイル・行番号だけです。訪問者の情報は保存しません。サイト自身のコードが投げた例外は、文面に顧客情報が入り得るので保存しません。

## 5. サポートで聞かれそうなこと

| 質問 | 答え |
|---|---|
| 検査が途中で止まる | ページを読み込み直して、もう一度ボタンを押します。検査済みのファイルは飛ばすので、続きから進みます。 |
| 「読み取れなかった」と出る | そのファイルは PHP 7.4 の文法でも 8.x の文法でも読めませんでした。壊れているか、PHP ではないファイルです。問題なしという意味ではありません。 |
| 「チェックの内側」とは | PHP の版を調べてから実行しているコードです。新しい PHP では実行されないはずなので、「動かなくなる」には数えません。 |
| 実行時の記録に何も出ない | 記録をオンにしてから、PHP がメッセージを出したときだけ記録されます。何も出ないのは、その期間に該当するメッセージがなかったということです。 |
| 記録に WordPress 本体のファイルが出る | 多くは、プラグインやテーマが本体の関数に古い渡し方をした結果です。メッセージの文面から呼び出し元を探します。 |
| 修正したのに、プラグインの更新で元に戻った | 更新は配布元のファイルで上書きします。配布元が直していなければ、更新後にもう一度修正します。Pro の「更新後の検査」をオンにすると、戻ったことに気づけます。 |
| 元に戻せないファイルがある | 修正のあとに変更されたファイルは、上書きすると新しい変更を失うので、そのままにします。元のファイルは `wp-content/uploads/upgrade-warden/backups/` にあります。 |
